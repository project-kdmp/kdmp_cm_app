# 2.1.3 (204)

2026-09-28 · 기준 버전 2.1.2(203)

**앱 동작은 2.1.2 와 같다.** 2.1.2 이후 커밋 9개가 전부 배포 경로와 문서다.

이 버전은 **Play 자동 업로드가 실제로 도는지 확인하기 위해 낸다.** 그전까지는
`--dry-run` 으로 업로드 직전까지만 확인했고, 인증과 권한은 읽기(`bootstrapListing`)
로만 봤다. 쓰기가 되는지는 올려봐야 안다.

동작 변경이 없는 버전을 검증에 쓰는 편이 안전하다. 업로드가 잘못 돌아도 내부
테스트 트랙에 2.1.2 와 같은 앱이 하나 더 놓일 뿐이다.

## 스토어 제출용 (Play Console 붙여넣기)

내부 테스트 트랙 전용이다. 프로덕션으로 승격하지 않는다.

```
내부 배포 경로를 점검하기 위한 빌드입니다.

```

## 자동화를 만들며 잡은 것

문서만 보고 짰으면 첫 실행에서 전부 터졌을 것들이다. `--dry-run` 을 실제로 돌려
하나씩 걸러냈다.

**`google-services.json`** — 사전 점검이 이 파일을 요구했는데 이 저장소에는 아예
없다. Firebase 를 `lib/firebase_options.dart` 로만 설정하고 Gradle 플러그인도 쓰지
않는다. 릴리스 빌드가 그 파일 없이 이미 성공하고 있었다.

**`dart analyze`** — `--fatal-warnings` 가 기본으로 켜져 있어 경고 하나에도 실패를
낸다. 이 저장소 기준선이 149건이라 **어떤 릴리스도 이 관문을 통과할 수 없었다.**
에러만 막는다.

**파이프 두 곳** — `flutter --version | head` 와 `unzip -l | grep -q`. 받는 쪽이
먼저 파이프를 닫으면 주는 쪽이 SIGPIPE 로 죽고 `pipefail` 이 그것을 실패로 친다.
서명이 멀쩡해도 검사가 늘 실패했다.

**출시노트 파일 이름** — 가장 조용한 것이었다. Play 의 internal 트랙에는
「1.7.2 버전 테스트2」가 출시노트로 남아 있었는데, gradle-play-publisher 는
`<트랙>.txt` 를 `default.txt` 보다 우선한다. 스크립트가 `default.txt` 에 쓰고
있었으므로 **내가 쓴 출시노트는 무시되고 저 낡은 문구가 올라갔을 것이다.**
연결만 확인하려고 돌린 `bootstrapListing` 이 이것을 드러냈다.
