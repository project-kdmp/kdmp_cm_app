# 2.2.0 (205)

2026-10-04 · 기준 버전 2.1.3(204)

**기사지정 기능을 담은 첫 버전이다.** 2.1.3 은 배포 경로 점검용이라 `lib/` 를 건드리지
않았으므로, 동작이 바뀌는 것은 2.1.2 이후 처음이다.

고객이 기사를 골라 지정해 호출한다. 지정 호출은 우선 배차 유효시간
(`kdmp_adm_feepolicy.timeout_min`) 동안 그 기사에게만 보이고, 시간이 지나면 조건이
저절로 풀려 전체 기사에게 공개된다.

## 스토어 제출용 (Play Console 붙여넣기)

내부 테스트 트랙 전용이다. 프로덕션으로 승격하지 않는다.

```
기사를 지정해 호출하는 기능이 추가되었습니다.

- 최근 이용한 기사, 단골 기사, 주변 대기 기사 목록에서 기사를 고를 수 있습니다.
- 이름 또는 기사번호로 기사를 검색할 수 있습니다.
- 자주 이용하는 기사를 단골로 등록해 둘 수 있습니다.
- 지정한 기사에게 먼저 배차를 요청하고, 일정 시간이 지나면 전체 기사에게 공개됩니다.
```

### 화면

- `driver_select_screen.dart` — 최근 이용·단골·주변 대기 탭과 이름·기사번호 검색
- `driver_detail_bottom_sheet.dart` — 기사 상세와 단골 등록·해제
- `appoint_wait_notice.dart` — 콜 진행 화면에 지정 기사와 남은 시한을 보여준다

### 서버 연동

즉시 호출과 예약 호출이 `appointDmSq` 로 지정 기사를 함께 보낸다. 지정한 기사가
퇴근·탈퇴 상태라 서버가 지정을 떼면 `appointReleased` 로 내려오고, 고객에게 알린
뒤 지정을 지운다. 고객이 모르고 일반 배차로 넘어가지 않게 하기 위한 것이다.

## 확인하지 못한 것

**실기기에서 기사지정을 눌러보지 않았다.** 지금까지 실기기 확인이 debug/STAGE 로만
이뤄졌고, 이 버전도 그렇다. 내부 테스트 트랙에 올리는 이유가 여기에 있다 — PROD 를
바라보는 릴리스 빌드로 다음을 실제로 확인해야 한다.

- 세 탭(최근 이용·단골·주변 대기)이 각각 기사를 채우는지
- 단골 등록·해제가 남는지
- 지정 호출이 그 기사에게만 보이고, 시한이 지나면 공개되는지
- 지정 기사가 퇴근 상태일 때 `appointReleased` 안내가 뜨는지

**`kdmp_cm_prefer_drv` 가 운영 DB 에 있는지 확인되지 않았다.** 이 테이블은 수동 적용
SQL(`db/manual/kdmp_cm_prefer_drv.sql`)로만 존재하고 적용 기록이 남아 있지 않다.
법인 선호기사 기능(`b2688090`) 때 들어갔을 가능성이 높지만 확인은 안 됐다.
**없으면 단골 탭이 운영에서 깨진다.** 내부 테스트에서 가장 먼저 볼 것이다.

**기사용 앱은 지정 콜을 화면에서 구별하지 못한다.** 서버가 콜 목록을 필터하므로
기능은 돌지만, 기사는 푸시로만 자신이 지정됐음을 안다. 의도한 범위인지 미확인이다.
