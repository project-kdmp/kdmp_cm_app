# 2.2.13 (219)

2026-11-02 · 기준 버전 2.2.12(218, 내부 테스트)

**인증 문자가 오면 인증번호가 저절로 채워진다.**

## 스토어 제출용 (Play Console 붙여넣기)

```
[새로워진 점]
· 인증 문자를 받으면 인증번호가 자동으로 입력됩니다.
```

## 서버는 이미 준비돼 있었다

이번에 붙인 것은 **앱 쪽 절반**뿐이다.

| | 상태 |
|---|---|
| 서버 문자 본문 | 이미 Android 형식 — `<#> [코드] …` + 끝에 `appSignature` |
| 서버 API | 이미 `appSignature` 를 받음 (`SendSmsCertCodeReqVO`) |
| 앱 요청 모델 | 이미 `appSignature` 필드 있음 — **값을 채우는 코드만 없었다** |

`<#>` 는 SMS Retriever API 의 필수 접두사다. 설계를 끝내 놓고 앱 구현만 멈춘 상태였다.
**서버는 한 줄도 고치지 않았다.**

## 어떻게 동작하나

`smart_auth` 로 앱 해시를 얻어 인증요청에 싣고, 같은 패키지로 문자를 기다린다.
칸에 6자리가 차면 **기존 리스너가 검증까지 자동으로 태운다** — 사용자는 아무것도
누르지 않는다.

**SMS 읽기 권한은 필요 없다.** Retriever 는 해시가 맞는 문자만 앱에 건넨다.

못 되는 경우를 전부 종전 동작으로 떨어뜨렸다.

- 해시를 못 얻으면 빈 문자열을 보낸다 — 자동입력만 안 되고 **인증은 된다**
- iOS 는 건너뛴다. OS 가 알아서 제안하고 서버도 iOS 용 본문을 따로 보낸다
- 사용자가 이미 손으로 넣었으면 **덮어쓰지 않는다**
- 화면을 떠나면 대기를 거둔다 — 남겨 두면 다음 문자까지 집어 간다

## 확인한 것

- `fvm flutter analyze` — 손댄 파일 `No issues found`
- Play 실물 조회로 다음 versionCode 를 정했다

## 확인하지 못한 것

- **기기에서 자동입력이 실제로 되는 것을 보지 못했다.** 기기가 연결돼 있지 않았다
- **앱 해시가 실제로 나오는지 확인하지 못했다.** 이 값이 비면 자동입력만 조용히
  안 되고 인증은 되므로, 겉으로는 드러나지 않는다

## 앱 해시는 서명마다 다르다

debug·업로드키·**Play 재서명본**이 각각 다른 값을 낸다. 코드가 실행 시점에 해시를
구하므로 자동으로 맞지만, **테스트는 내부 테스트 빌드로 해야 확실하다.**
